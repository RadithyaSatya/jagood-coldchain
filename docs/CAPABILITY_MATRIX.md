# JaGOOD Capability and Claim Matrix

This file describes the repository as implemented today. Product proposals and PRDs may describe future scope; they are not evidence that a capability exists.

## Implemented capabilities

| Capability | Status | What the implementation actually does | Important boundary |
|---|---|---|---|
| Quality-risk classification | Implemented, experimental | A persisted XGBoost pipeline classifies generated route candidates as Low, Medium, or High and produces a weighted risk score. | Training rows and labels are synthetic. Metrics measure recovery of the synthetic label function, not real-world spoilage accuracy. |
| Model training and evaluation | Implemented | Reproducible scripts generate seeded synthetic data, train the preprocessing/model pipeline, and evaluate a held-out synthetic split. | No real labelled shipment outcome dataset is used. |
| Smart Route Planner | Implemented, MVP | Generates land and/or multimodal candidates, enriches them, performs model inference, and ranks them by risk or speed. | It is not an industrial routing optimizer or navigation system. ORS failures use haversine-based estimates. |
| Scenario Simulator | Implemented, deterministic | Compares a baseline with changes to delay, mode, cooling equipment, or insulation by re-running the route-risk pipeline. | No Monte Carlo engine, learned scenario model, or uncertainty distribution is implemented. |
| Maritime risk input | Implemented with explicit fallback | Uses BMKG maritime/port forecasts when reachable and derives a port-risk proxy from wave category. Expected network/malformed-response failures use neutral fallback values labelled in `environmental_data_quality`. | Port status is not official operational status and `searoute-py` geometry is not navigation-grade. Fallback values reduce demo failure, not uncertainty. |
| Passive cargo-temperature simulation | Implemented, assumption-based | Simulates passive cargo temperature with an exponential heat-transfer model using Open-Meteo ambient temperature or a synthetic fallback. | Reefer shipments assume ideal cargo temperature. There are no physical sensors, calibration data, or remaining-shelf-life output. |
| SHAP explanation factors | Implemented | Computes per-route SHAP contributions and renders the strongest qualitative factors. | Contributions are combined in raw-margin space and are not an exact probability decomposition. |
| AI Explain | Implemented, optional LLM | Sends structured analytical facts to an OpenAI-compatible LLM for natural-language explanation. | The LLM does not calculate routes or risk. A deterministic fact-only fallback is used when inference is unavailable. |
| Offline golden demo | Implemented | Tests route fallback, risk/SHAP inference, scenario comparison, and AI Explain fallback without ORS or an LLM. | It demonstrates technical integration, not external-data availability or real-world accuracy. |

## Data truth table

| Data | Classification | Current use |
|---|---|---|
| Commodity profiles | `DEMO` | Manually curated MVP assumptions. They are explicitly not FoodKeeper-derived. Metadata is exposed at `GET /commodities/provenance`. |
| Model training shipments and risk labels | `SYNTHETIC` | Generated by seeded rules plus noise for training and evaluation. |
| Historical delay/damage features | `DERIVED` from synthetic corridor assumptions | Deterministic priors used at training and inference; not observed shipment history. |
| OpenRouteService route response | External runtime data | Used for land geometry/duration when available; otherwise marked `data_quality: estimated`. |
| BMKG maritime forecast | External runtime data with labelled fallback | Used for sea/port enrichment when reachable. Responses are cached; expected failures use neutral defaults labelled `fallback`/`partial`. Land conditions are labelled `configured`. |
| Open-Meteo temperature | External runtime data with synthetic fallback | Used only for passive cooling simulation. |

## Not implemented

- GPS or IoT ingestion and real-time shipment monitoring
- persisted current-shipment workflow
- a separately trained delay-prediction model
- remaining shelf-life or guaranteed product-quality estimation
- economic-loss estimation
- Monte Carlo simulation or quantified uncertainty intervals
- feature store
- reinforcement-learning route optimization
- authentication, notifications, and production authorization controls

These items may appear in proposal or roadmap material only as future scope. They must not be presented as working features during the MVP demo.
