# Checklist Kesesuaian Proposal dengan MVP JaGOOD

Audit repository terhadap `Proposal Jagood.docx`, terakhir diperbarui 23 Agustus 2026 setelah penggabungan pembaruan *hackathon readiness*. Status kesesuaian: ✅ sesuai, ⚠️ sesuai sebagian/perlu memperjelas batasan, ❌ belum ada atau tidak sesuai. Kelayakan penyesuaian: **BISA** = dapat dikerjakan dari repository, **BERSYARAT** = membutuhkan data/sumber/keputusan tambahan, **TIDAK BISA DENGAN CODING SAJA** = membutuhkan validasi atau kegiatan eksternal, dan **TIDAK PERLU** = implementasi sudah memadai. Label **SELESAI (kode)** menunjukkan tindak lanjut implementasi telah dikerjakan, sedangkan **BELUM (proposal)** menunjukkan perubahan masih harus dilakukan di dokumen proposal dan tidak termasuk commit kode.

## Checklist Penerapan Perubahan ke Dokumen Proposal

Bagian ini digunakan untuk melacak perubahan pada `Proposal Jagood.docx`, bukan status implementasi kode. Tanda `[x]` berarti dukungan kode yang diperlukan sudah tersedia. Tanda `[ ]` berarti redaksi atau bukti tersebut masih harus diterapkan dan diperiksa langsung di dokumen proposal. Jangan mengubah `[ ]` menjadi `[x]` hanya karena fitur sudah tersedia di repository.

### Dukungan kode yang sudah selesai

- [x] Smart Route Planner, XGBoost, risk ranking, confidence score, dan SHAP tersedia.
- [x] Scenario Simulator membandingkan baseline dengan perubahan delay, moda, pendingin, dan insulasi.
- [x] Data BMKG maritim/pelabuhan dan Open-Meteo darat memiliki fallback serta provenance.
- [x] Shipment store, prediction snapshot, rute terpilih, checkpoint, dan pelaporan outcome tersedia.
- [x] Estimasi delay berbasis bootstrap/statistik adaptif tersedia untuk lingkup MVP.
- [x] Sisa umur simpan, persentase sisa, dan status kualitas tersedia sebagai proxy MVP.
- [x] FastAPI platform gateway menjadi satu-satunya API publik untuk kedua frontend.
- [x] Final Recommendation diorkestrasi oleh FastAPI gateway.
- [x] AI Explain hanya menjelaskan fakta analitik dan memiliki fallback deterministik.
- [x] Docker Compose menghubungkan gateway, service internal, PostgreSQL, dashboard, dan chatbot.
- [x] Golden demo dan fallback offline tersedia.

### Redaksi proposal yang masih harus diperbarui

- [ ] **Posisi produk:** pastikan JaGOOD disebut *decision-support system*, bukan sistem monitoring/IoT produksi.
- [ ] **Dataset model:** nyatakan training, validation, dan test masih berasal dari dataset sintetis; metrik bukan bukti akurasi dunia nyata.
- [ ] **Historical Shipment:** nyatakan repository belum berisi data shipment aktual yang memadai. Sistem baru menyediakan infrastruktur untuk mengumpulkan planned-vs-actual melalui pilot.
- [ ] **Commodity Database:** pisahkan atribut `REFERENCE` (temperatur dan umur simpan) dari atribut `DEMO` (delay tolerance dan sensitivitas temperatur).
- [ ] **Sumber lingkungan:** tulis BMKG untuk maritim/pelabuhan dan Open-Meteo untuk cuaca darat/suhu ambient; jangan menyatakan seluruh data berasal dari BMKG.
- [ ] **Preprocessing:** sebut validasi skema dan encoding; jangan mengklaim cleaning data historis mentah atau normalisasi numerik yang tidak dilakukan.
- [ ] **Feature Store:** ganti menjadi “shared feature pipeline dan PostgreSQL prediction/feature snapshot”; jangan mengklaim Feature Store industri.
- [ ] **Safety check:** jelaskan sebagai peringatan/demosi rute, bukan keputusan resmi penutupan pelabuhan atau pemblokiran rute.
- [ ] **Scenario Simulator:** batasi input langsung ke delay, moda, pendingin, dan insulasi. Cuaca/gelombang/suhu belum dapat di-*override* langsung oleh pengguna.
- [ ] **Delay Estimation:** jelaskan sebagai pendekatan hybrid bootstrap transparan dan statistik outcome/checkpoint, bukan model ML regresi delay tervalidasi.
- [ ] **Estimated Product Quality:** gunakan output `remaining_shelf_life_hours`, `remaining_shelf_life_pct`, dan `quality_status`; tambahkan disclaimer bahwa hasil bukan jaminan keamanan pangan.
- [ ] **Arsitektur backend:** gambar frontend hanya terhubung ke FastAPI platform gateway; Route Planner dan AI Explain berada sebagai service internal modular.
- [ ] **Final Recommendation:** jelaskan sebagai orkestrasi analitik di gateway, bukan model AI baru atau proses perhitungan oleh LLM.
- [ ] **LLM:** tegaskan bahwa LLM tidak menghitung rute, risiko, delay, atau kualitas dan hanya menyusun penjelasan dari fakta terstruktur.
- [ ] **SHAP:** jelaskan faktor secara kualitatif dan jangan menyebut kontribusinya sebagai persentase penyebab kerusakan.
- [ ] **PostgreSQL:** cantumkan fungsi cache, shipment record, prediction snapshot, checkpoint, outcome, statistik koridor, dan statistik delay cuaca.
- [ ] **Monitoring:** tulis checkpoint geolocation manual sebagai kemampuan pilot; GPS/IoT kontinu, autentikasi, notifikasi, dan fleet monitoring tetap *future work*.
- [ ] **Business value:** gunakan kata “ditujukan”, “diharapkan”, atau “berpotensi”; jangan menyatakan pengurangan kerusakan/biaya sudah terbukti.
- [ ] **Governance data:** masukkan klasifikasi `REAL`, `REFERENCE`, `DERIVED`, `SYNTHETIC`, dan `DEMO` beserta contoh penggunaannya.
- [ ] **Daftar pustaka:** hapus referensi yang tidak relevan dan tambahkan sumber cold-chain, FAO/UNEP, XGBoost, SHAP, Q10, routing, BMKG, Open-Meteo, FDA, USDA/FSIS, UC Davis, dan IDFA yang benar-benar digunakan.
- [ ] **Nama dan format:** konsisten menggunakan `JaGOOD (Jaga Food)`, perbarui daftar isi, penomoran, caption, referensi silang, dan lampiran bukti implementasi.

### Validasi eksternal yang belum dapat dicentang

- [ ] Dataset planned-vs-actual nyata sudah terkumpul dalam volume yang memadai.
- [ ] Model risiko sudah dievaluasi terhadap outcome shipment nyata.
- [ ] Model ML delay khusus sudah dilatih dan diuji secara kronologis, jika tetap ingin diklaim.
- [ ] Proxy kualitas sudah divalidasi dengan pengukuran produk atau sensor fisik.
- [ ] Dampak bisnis sudah diukur melalui pilot dan perbandingan sebelum–sesudah.

Setelah semua perubahan redaksi selesai diterapkan ke `Proposal Jagood.docx`, lakukan audit ulang terhadap nomor 1–27 dan ubah checkbox proposal yang sudah diverifikasi menjadi `[x]`.
